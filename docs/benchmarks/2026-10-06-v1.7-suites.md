# v1.7 benchmark suites: local patterns, live sites, navigation (2026-10-06)

The three suites that earlier reports ran on 1.3.2/1.4, **re-run on 1.7.x** so that every figure the docs quote is current. Together with the
tool-vs-tool comparison ([competitors-v1.7](2026-10-06-competitors-v1.7.md)) this is the 1.7 benchmark set. Raw data: `raw/2026-10-06/v1.7-*.jsonl`.

## Protocol fields (per `docs/benchmark_protocol.md`)

| Field | Value |
|---|---|
| Date (UTC) | 2026-10-06, evening |
| Code under test | `sb` 1.7.1 (working tree = tag `v1.7.1`) |
| Environment | macOS 24.6 arm64, Python 3.12.12, Playwright 1.58.0, bundled Chromium, headless; a normal desktop with the user's own Chrome also running (load average ~3) |
| "Planner" | **No LLM.** A scripted *oracle*: each step may only act on something the tool actually showed it, chosen by label (`scripts/dogfood/runner.py`). It measures the tool layer, not a model's judgement. Raw Playwright = full `aria_snapshot` per step, oracle picks locators perfectly (an idealised "classic agent": it does **not** wait for the page to settle) |
| Runs | local: 3 reps x 9 scenarios per method; live: 3 **interleaved** rounds (`sb`, then raw Playwright, then `sb --lite media`, repeated) x 8 sites; navigation: 3 reps x 8 URLs, warm and cold cache |
| Aggregation | success count; median wall time; median tokens (chars/4) of everything the model had to read |

Running one method after another on live sites let network drift masquerade as a regression in an earlier attempt (`sb` looked 50 % slower than
in 1.4; the same sites timed the same on 1.5.0 and 1.7.1 side by side). Hence the interleaving.

| hover_menu | 3/3 · 0.4 s · 0.1k | 3/3 · 0.4 s · 0.1k |
| iframe_payment | 3/3 · 0.4 s · 0.1k | 3/3 · 0.4 s · 0.1k |
| lazy_feed_item35 | **0/3** · 2.6 s · 0.2k | 3/3 · 0.5 s · 0.8k |

Raw Playwright fails the lazy feed (item 35 is not in the snapshot until scrolled, and nothing says to scroll; `sb` prints `... more below`) and the six

## 2. Eight live sites (24 runs per method)

Wikipedia, Hacker News, GOV.UK, GitHub, BBC Sport, DuckDuckGo, NHS, Amazon UK; each is a short search/open task, read-only.

| Site | raw Playwright | `sb` | `sb --lite media` |
|---|---|---|---|
| amazon_search | **0/3** · 2.1 s · 11.7k | 3/3 · 4.7 s · 2.6k | 3/3 · 4.0 s · 2.5k |
| bbc_sport_football | 3/3 · 1.6 s · 55.0k | 3/3 · 2.0 s · 3.9k | 3/3 · 2.0 s · 3.9k |
| ddg_search | 3/3 · 0.7 s · 1.0k | 3/3 · 2.2 s · 1.9k | 3/3 · 1.1 s · 1.9k |
| github_issues | 2/3 · 1.1 s · 17.3k | 3/3 · 1.7 s · 2.6k | 3/3 · 1.7 s · 2.6k |
| govuk_search | **0/3** · 6.5 s · 6.1k | 3/3 · 1.2 s · 2.6k | 3/3 · 1.4 s · 2.6k |
| hn_comments | 3/3 · 1.4 s · 127.9k | 3/3 · 2.3 s · 2.5k | 3/3 · 2.3 s · 2.5k |
| nhs_search | 3/3 · 1.0 s · 5.7k | 3/3 · 1.5 s · 1.8k | 3/3 · 1.7 s · 1.8k |
| wikipedia_search | 3/3 · 0.9 s · 94.4k | 3/3 · 1.1 s · 2.5k | 3/3 · 1.3 s · 2.5k |
| **Total** | **17/24** · 1.37 s · 12.6k median (max 161k) | **24/24** · 1.93 s · 2.5k (max 3.9k) | **24/24** · 1.69 s · 2.5k |

- **`sb` completes all 24 and reads about 5x fewer tokens at the median (about 50x fewer on Hacker News, 38x on Wikipedia).** Raw Playwright's runs on
  Amazon and GOV.UK, and one on GitHub, did not reach the expected result (the scripted success check failed; GOV.UK also took 6.5 s).
- **`sb` is slower in wall time: about 0.5 s more per task at the median** (1.93 s vs 1.37 s; DuckDuckGo 2.2 s vs 0.7 s). Each `sb` step waits for the
  page to settle (typically 0.2-0.4 s of DOM quiet) so that what the model reads is the page *after* the action; the idealised raw-Playwright step
  snapshots immediately, which is faster and sometimes wrong. A per-step profile (NHS click: 78 ms execute + 427 ms settle + 13 ms read) confirms the
  settle is the cost. It is deliberate and was not loosened.
- **Not a regression:** the same four sites timed within noise on tag `v1.5.0` and on 1.7.1 when run interleaved side by side (median 1.49-1.64 s vs 1.48-1.51 s).
- `--lite media` (skip images/fonts/video, no animations): 1.69 s vs 1.93 s here, which is within the run-to-run swing of these live sites (DuckDuckGo 1.1 s vs 2.2 s is one site). Section 3 shows no gain on navigation. Still **opt-in and unproven**.

## 3. Navigation: time and tokens to a usable page (8 URLs x 3 reps)

| Method | warm cache | cold cache | tokens read |
|---|---:|---:|---:|
| httpx (no JavaScript, raw HTML) | 35 ms | 34 ms | 38,842 |
| Playwright `domcontentloaded` + aria snapshot | 157 ms | 251 ms | 5,497 |
| Playwright `load` + aria snapshot | 218 ms | 292 ms | 5,497-6,985 |
| **`sb` 1.7** | **339 ms** | **434 ms** | **1,281** |
| `sb --lite media` | 417 ms | 439 ms | 1,281 |
| `sb --lite max` | 388 ms | 420 ms | 1,281 |

`sb` takes ~120-180 ms longer than Playwright's own `goto` (it settles and builds the view) and hands the model 4-5x fewer tokens (30x fewer than the
raw HTML, which also cannot run JavaScript: Wikipedia's HTML alone is 325k tokens). It is not "as fast as httpx"; httpx only fetches bytes.
Lite mode does not speed this up (417-439 ms vs 339-434 ms). Not tested: slow or metered networks, where it should help.

## What changed since the 1.4 numbers

| | 1.4 report | 1.7 now |
|---|---|---|
| Local suite, `sb` | 27/27, 0.44 s, 159 tok | 27/27, 0.47 s, 150 tok |
| Live suite, `sb` | 16/16, 1.43 s, 2.5k tok | 24/24, 1.93 s (interleaved), 2.5k tok |
| Navigation, warm | 303 ms, 1,280 tok | 339 ms, 1,281 tok |

Same success and tokens, a few percent slower on local and navigation; the live-suite difference is network drift plus the interleaved method
(a side-by-side with 1.5.0 shows no change). 1.7 adds capabilities (drag, upload, canvas CAPTCHAs, shadow-DOM modals, hung-script handling) that these suites
do not exercise, so no speed-up should be expected here.
